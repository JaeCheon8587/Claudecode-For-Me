# 세션 브리핑

여러 세션을 오가다 이 세션에 돌아온 사용자가 **"여기서 뭘 하고 있었지, 이제 뭘 하면 되지?"** 를 한 화면으로 파악하게 한다.
근거는 이 세션의 대화(맥락 압축 요약 포함)와 아래 작업 상태뿐이다. 보고만 한다 — 파일을 고치지 않는다, 커밋 · push 하지 않는다,
멈춰 있던 작업을 이어서 하지 않는다.

## 작업 상태 (호출 시점 실행 결과)

브랜치 · 원격 대비 · 미커밋:
!`git status --short --branch 2>&1 || echo "(git 레포 아님 — 작업 상태 생략)"`

최근 커밋:
!`git log --oneline -8 2>&1 || echo "(커밋 기록 없음)"`

이 세션이 다른 폴더(워크트리 등)에서 작업했다면 그 폴더에서 같은 읽기 전용 명령(`git -C <폴더> status --short --branch`,
`git -C <폴더> log --oneline -8`)으로 확인한다.

## 절차

1. **현재 주제를 정한다 — 마지막 대화 기준.** 마지막 사용자 요청에서 거슬러 올라가, 목표가 무관한 쪽으로 바뀐 지점까지가 현재 주제다.
   같은 결과물을 이어서 다루는 요청(그 작업의 수정 · 커밋 · push)은 같은 주제로 묶는다. `/session-brief` 호출과 그 출력은 제외한다 —
   직전 브리핑은 주제도 마지막 수행 내용도 아니다.
2. **남은 일을 세션 전체에서 모은다** — 이전 주제도 포함한다.
   - 세션이 사용자에게 묻고 답을 기다리며 멈춘 것
   - 시작했지만 끝내지 못한 단계
   - 사용자에게 안내한 후속 조치(재시작 · 수동 실행 등)

   이후 대화에서 해결된 항목은 뺀다. 해결 여부를 대화로도 작업 상태로도 확인할 수 없으면 "(미확인)" 을 붙인다.
3. **작업 상태를 읽는다** — 브랜치, 원격 대비 ahead/behind(= 미푸시 · 미풀), 미커밋 파일(`??` 미추적 포함). 원격 추적이 없는
   브랜치면 "원격 추적 없음(push 안 됨)". git 레포가 아니면 `[작업 상태]` 줄을 통째로 생략한다.
4. **아래 양식으로 보고한다.**

## 보고 양식

```
## <현재 주제 — 한 줄 이름>

### 기능
- <기능 — 무엇을, 왜>
  - <세부 — 의도 · 이유 · 결정>

### 맥락
- <어떤 흐름으로 여기까지 왔는지 — 요청 → 판단 → 전환점>

### 마지막 수행 내용
- <무엇을 하고 있었고 어디까지 진행됐는지>

### 남은 일 · 대기 중
- [결정 대기] <세션이 사용자에게 묻고 멈춘 것>
- [미완료] <시작했지만 끝내지 못한 단계>
- [작업 상태] <브랜치> · 미커밋 N · 미푸시 N
- [이전: <이전 주제>] <이전 주제의 미결 사항>
```

기능 섹션의 수준 — 코드 식별자 없이 의도 · 이유 · 결정을 쓴다:

```
### 기능
- 데이터 접근을 전담할 신규 서비스 기반 구성
  - 향후 DB 조회·갱신 기능을 분리할 수 있도록 실행 호스트와 계층별 프로젝트 골격 추가
  - 설정 로드·로그·Swagger·Windows 서비스 실행 구조 구성
- 서비스 생존 확인 기능 추가
  - ApiGateway에 주기적으로 하트비트를 보내는 기능 개발
  - 실제 DB·메시지 큐 점검이 미구현인 상태는 정상으로 표시하지 않고 UNKNOWN으로 반환
```

## 작성 규칙

- **드릴다운 최대 3단계** — 주제 → 기능 → 세부.
- **기능 · 의도 · 이유 · 결정 수준으로 쓴다.** 파일 경로 · 함수명 · 클래스명 같은 코드 식별자는 쓰지 않는다. 예외는 남은 일 —
  사용자가 행동하는 데 필요하면 쓴다(예: 커밋 안 된 파일 이름).
- **한 화면, 30줄 이내.** 넘치면 기능 섹션부터 줄인다 — 마지막 수행 내용과 남은 일은 줄이지 않는다. 돌아온 사람에게 가장 필요한
  두 섹션이다.
- **본문(기능 · 맥락 · 마지막 수행 내용)은 현재 주제만.** 이전 주제는 미결이 있을 때만 `[이전: <주제>]` 줄로 나온다.
- **네 섹션 헤더는 항상 쓴다** — 세션마다 같은 자리에서 찾게 한다. 쓸 내용이 없는 섹션은 `- 없음`.
  예외는 진행한 작업이 없는 세션 하나뿐이다(정확성 규칙 5).
- 남은 일 안에서는 해당 항목이 없는 태그 줄을 쓰지 않는다.
- 대화에 쓴 언어로 쓴다.

## 정확성 규칙

1. **"완료" 는 증거가 대화에 있을 때만 쓴다** — 커밋, 테스트 통과 출력, 사용자 승인. 없으면 "작업함 (검증 미확인)".
2. **작업 상태는 실행 결과로만 쓴다** — 위 주입 결과(또는 다른 폴더에서 실행한 결과). 대화 속 기억으로 쓰지 않는다.
3. **맥락 압축으로 세부를 잃은 구간은 지어내지 않는다** — "(압축 이전 — 세부 불명)" 으로 적는다.
4. **`/session-brief` 호출과 그 출력은 보고 전체에서 제외한다** — 주제 · 기능 · 맥락 · 마지막 수행 내용 · 남은 일 어디에도 쓰지 않는다.
5. **진행한 작업이 없는 세션**(막 시작한 세션)이면 양식을 채우지 않고 "이 세션에서 진행한 작업 없음" 한 줄과 `[작업 상태]` 만
   보고한다. git 레포가 아니면 그 한 줄만.
